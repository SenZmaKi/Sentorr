## Contracts and trade-offs

State-domain writes retain optimistic UI publication but track failed persistence
so an identical restore retries disk. Pairing and enqueue require persistence
before granting authorization or starting work. These are domain boundaries,
not a transaction spanning history, following and lists.

Shutdown continues after failures and reports them in diagnostics; a successful
exit does not assert that a failed checkpoint became durable. Startup cleanup
owns only resources acquired during that attempt. Unknown queue versions are
preserved and exposed through the recovery UI rather than silently downgraded.

Metadata identity checks add bounded pure-Dart framing/hash work before native
parsing. Storage promotion waits for a native alert (30-second timeout). Missing
finished-file classification uses the existing synchronous filesystem boundary;
external-volume latency and file changes after classification remain possible.

Copy cancellation uses an operation-owned HTTP client, preserving unrelated peer
traffic. Revocation checks cover authorization before response publication;
unpairing does not retroactively retract bytes already sent to a peer.
